# AI 활용 기록

강화학습 수업 기말 프로젝트(퓌에르토리코 2인 에이전트 Moka)를 만들면서 AI(Claude)를 어떻게 썼는지 정리한 기록. 실험별 자세한 내용은 [docs/experiments](experiments/README.md)에 있고, 이 문서는 그 과정에서 AI와 어떻게 일을 나눴는지를 중심으로 씀.

> 진행 중인 프로젝트. 수업 리그전(11/19, 11/24, 11/26, 11/28)과 코드 제출(11/29)까지 계속 이어서 기록함. 마지막 업데이트: 2026-11-10 (Moka v3 채택).

## 일을 나눈 방식

처음에 정한 규칙은 "AI가 혼자 완성하지 않고 같이 완성한다".

- AI: 개념 설명, 실험 설계 제안, 학습·분석 코드 작성, 결과 해석 초안
- 나: 모든 명령을 직접 실행, 결과를 보고 다음 단계 결정, 채택 여부 판단, 기록 검토, 측정 기준 정하기 (예: 모든 상대를 1000판으로)
- AI가 코드를 쓰면 무엇을 왜 바꿨는지 설명을 듣고, 바꾼 곳에는 `[Moka]` 표시를 남김

강화학습은 이번 학기에 처음 배우는 거라, 새 개념이 나오면 그 개념을 이해하는 데 필요한 것부터 설명해 달라고 함 (PPO, kl, greedy와 sampled, 시드, 95% 범위 등).

## 지킨 규칙

교수님이 "AI를 쓰다 보면 AI가 모르는 사이에 네트워크에 접근하거나, 웹에서 찾은 치팅 방식을 자연스럽게 쓸 수 있다. 걸리면 자동 F"라고 강조하심. 그래서 프로젝트 시작 때 아래를 정함.

- 이 프로젝트에서는 AI가 웹 검색으로 에이전트를 강하게 만드는 방법을 찾지 않음. 외부 코드도 가져오지 않음. README 작성법처럼 에이전트와 상관없는 것만 검색함
- 제출 코드(act())에는 대회 금지 항목(네트워크, 파일 쓰기, 스레드 수 변경, 숨겨진 정보 읽기 등)이 들어가지 않게 하고, 가중치를 바꿀 때마다 조교 검증 도구를 돌림
- 조교 공지가 나오면 바로 반영 (스레드 1개 환경, 가중치는 state_dict로 저장 등)

## 날짜별 기록

### 11/5: 개발 환경, 기준선 측정

- 수업 안내 PDF와 조교 저장소를 AI와 같이 읽으며 규칙과 구조를 파악함. Python 3.12 가상환경 구성.
- 조교 제공 PPO가 TradeBuilding, ActionValue 상대로 얼마나 이기는지 측정.
- 50판 결과를 보고 "TradeBuilding이 약점"이라고 해석했는데, 200판·1000판으로 다시 재 보니 두 상대 모두 약 89~90%로 같았음. 해석을 철회하고, 50판은 판 운으로 ±10%p 흔들린다는 걸 기준으로 삼음. 1000판 결과를 보기 전에 내가 예상한 값(92%, 84%)도 빗나감.
- [실험 00](experiments/2026-11-05_00_baseline.md)

### 11/6: 이긴 판과 진 판 비교, 측정 방법 바꾸기

- AI에게 게임 기록 분석 스크립트를 부탁함 (이긴 판·진 판 점수 구성 비교, 라운드별 요약).
- 진 판 하나를 라운드별로 직접 읽으면서, 건축가 역할을 상대에게 계속 내주고 광부를 자주 고르는 경향을 찾음.
- 같은 가중치끼리 붙였는데 43%가 나옴. 같은 실력이면 50%여야 하므로 측정 도구를 의심했고, play.py가 판마다 좌석까지 같이 바꿔 좌석 운이 섞인다는 걸 확인함. 좌석을 바꿔 두 번씩 두는 조교 리그전 도구로 측정 방법을 바꿈.
- 기본 봇 8종 상대로 측정해 보니 진짜 강적은 탐색 봇(SearchLite 33%, Search 32.5%)이었음.
- 조교 공지(채점은 CPU 스레드 1개)대로 검사하자 첫 수가 1.8초 걸려 시간 초과가 남. 게임 시작 전에 한 번 미리 계산하는 예열을 넣어 해결.
- [실험 01](experiments/2026-11-06_01_win-loss-comparison.md), [실험 02](experiments/2026-11-06_02_evaluation-method.md)

### 11/7: 상대를 섞어서 이어서 학습하기 → Moka v1

- 자기 자신하고만 두던 학습에 기본 봇과 원본 체크포인트를 섞는 설계를 AI와 같이 정함. 비율은 AI 제안을 받아 내가 결정.
- 시운전에서 학습률 3e-4로 이어서 학습하자 kl이 0.72로 튀고 원본 상대 승률이 오히려 떨어짐. 원인은 조교 학습이 학습률을 0까지 낮추며 끝났는데 다시 크게 시작한 것. 1e-5로 낮추자 kl 0.013으로 안정됨.
- 학습 중 승률은 sampled(확률적으로 수를 고름)라 실제 제출 방식(greedy)보다 낮게 나온다는 걸 같은 실력끼리의 실험으로 확인하고, 판정은 리그전으로만 하기로 함.
- 실험용 시드, 최종 확인용 시드, 아직 쓰지 않은 시드를 나눠 쓰기로 함. 같은 판만 계속 보면 그 판들에 맞춰질 수 있어서.
- [실험 03](experiments/2026-11-07_03_mixed-opponents.md)

### 11/8: 더 오래 학습하기, 과거의 나와 연습하기 → Moka v2

- 밤새 돌린 리그전이 멈춘 것처럼 보였을 때 AI가 다시 시작하라고 잘못 안내함. 이후 리그전 도구가 한 쌍을 한 작업으로 묶어 느린 쌍이 끝까지 남는 구조라는 걸 확인하고, 다시 시작할 필요가 없었다고 정정함. 이때 노트북이 배터리·절전 상태였던 것도 찾아서 전원 설정을 바꿈.
- 200판 리그전에서 "과거의 나와 연습하면 SearchLite 상대가 9.5%p 좋아진다"는 결과가 나왔는데, 1000판으로 다시 재니 3.7%p로 줄어서 "약한 경향"으로만 기록함.
- Moka v1 상대 1000판 65.3% 등으로 채택 기준을 통과해 Moka v2로 교체. 기본 봇 상대 1~2판 차이를 하락으로 볼지 애매해서 채택 기준 문구를 "의미 있는 하락 없음"으로 고침.
- [실험 04](experiments/2026-11-08_04_longer-and-past-self.md)

### 11/9: 포화 확인, 탐색 봇과 연습하기

- 실험 5(학습량만 늘리기)와 실험 6(SearchLite를 연습 상대에 10% 추가)을 같은 출발점, 같은 학습량으로 설계함. 실험 5가 실험 6의 대조군이 되게 해서, 바꾼 것 하나의 효과만 보이게 함.
- AI가 학습 코드를 다시 읽다가 학습률이 학습 끝에 저절로 0이 된다는 걸 확인함. 그러면 마지막 체크포인트들이 비슷한 건 실력이 한계라서가 아닐 수 있어서, 포화를 판단하는 방법을 바꿈.
- 탐색 봇을 섞은 학습이 예상보다 4배 넘게 느렸음. 충전기를 안 꽂아 둔 상태였고, 꽂은 뒤 약 45% 빨라짐.
- [실험 05](experiments/2026-11-09_05_saturation.md)

### 11/10: 리그전, 최종 확인 → Moka v3

- 실험 5·6 체크포인트 7개를 한 리그전에 넣어 비교함. AI는 SearchLite 쌍이 1~3시간 걸릴 거라고 했는데 실제로는 25분이었음. 학습할 때와 리그전에서 SearchLite가 시간을 쓰는 방식이 다르다는 걸 놓친 예측이었음.
- 200판 리그전을 보고 AI가 "학습량만으로는 SearchLite 상대가 안 는다"고 해석했는데, 처음 보는 1000판에서는 조금 올랐음. 해석을 고치고 기록에도 고친 이유를 남김. 200판으로 강하게 결론 내리지 않는다는 원칙을 다시 확인함.
- 후보를 200판으로 고르고, 고른 후보만 처음 보는 판 1000판으로 확인하는 순서를 지킴. 여러 후보 중 1등을 고른 판으로 그 1등을 다시 평가하면 운이 실력처럼 보이기 때문.
- 학습에 쓰지 않은 Search, MCTS 상대도 같이 올랐는지 확인하고 나서 채택함 (Search 57.5% → 78.0%). SearchLite 하나만 공략한 게 아니라는 근거.
- Search, MCTS 확인이 200판뿐이라는 걸 보고, 시간이 오래 걸려도 모든 상대를 1000판 기준으로 확인하기로 정함. AI가 그동안 리그전 도구가 한 쌍을 작업자 하나에 맡겨 나머지 작업자가 놀고 있었다는 걸 놓치고 있었는데, 이걸 왜 이제야 말하냐고 짚었음. 그 뒤로 시드를 여러 묶음으로 나눠 동시에 돌리는 방식을 모든 리그전에 쓰기로 함.
- AI가 "가중치가 이미 공개 저장소에 올라가 있다"고 했는데, 확인해 보니 가중치 파일은 처음부터 .gitignore로 제외돼 한 번도 올라간 적이 없었음. 대회가 끝날 때까지 가중치는 올리지 않기로 정함.
- [실험 06](experiments/2026-11-10_06_searchlite.md)

## AI가 틀렸던 것과 잡은 방법

| 무엇이 틀렸나 | 어떻게 알았나 |
|---|---|
| 50판 결과로 약점을 잘못 해석함 | 판 수를 늘려 다시 잼 |
| 같은 가중치끼리 43% (측정 도구 문제) | "같은 실력이면 50%"라는 기대값과 비교 |
| 이어서 학습할 때 학습률을 그대로 둠 | 시운전에서 kl과 원본 상대 승률을 확인 |
| 리그전이 멈췄다고 보고 재시작을 안내함 | 도구 구조를 확인하고 정정 |
| 200판에서 본 효과를 크게 봄 | 1000판으로 다시 잼 |
| 학습률이 끝에 0이 되는 걸 몰라 포화 판단 기준이 틀릴 뻔함 | 학습 코드를 다시 읽어서 확인 |
| 리그전 시간을 1~3시간으로 예측 (실제 25분) | 실제 진행 기록과 비교 |
| 200판 리그전으로 "학습량만으로는 안 는다"고 해석 | 처음 보는 1000판으로 다시 잼 |
| 느린 쌍이 작업자 하나를 붙잡는 동안 나머지가 노는 걸 놓침 | 내가 짚어서 시드를 나눠 돌리는 방식으로 바꿈 |
| 가중치가 공개돼 있다고 잘못 말함 | git ls-files로 확인 |

AI의 해석은 측정으로 확인되기 전까지 가설로만 둠. 판 수를 늘리고, 처음 보는 시드로 다시 재고, 같은 실력끼리의 기대값과 비교하는 방식으로 확인함.

## 기록을 남긴 방식

- 처음에는 실험 결과를 대화로만 주고받았음. AI가 기록을 따로 남기지 않아서 계속 써 달라고 요구했고, 그 뒤로 실험 하나당 파일 하나(날짜_번호_제목.md)로 남김.
- 기록에는 목적, 설계, 실행 명령, 결과 표, 해석, 다음에 할 것을 적음. 해석이 나중에 틀린 걸로 밝혀지면 지우지 않고 철회했다고 적음.
- 기록 초안은 AI가 쓰고, 내가 읽고 고친 뒤 커밋함.
