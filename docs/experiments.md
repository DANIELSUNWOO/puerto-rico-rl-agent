## 실험 0: 기준선 (2026-11-05)

- 에이전트: 조교 제공 PPO (examples/ppo_entry, ppo_baseline_2p.pt)
- 측정: play.py, 상대 5종 x 50판, 0.1초 제한

| 상대 | 승률 | 승-패 | 점수 차 |
|---|---|---|---|
| Random | 100% | 50-0 | +31.9 |
| Factory | 98% | 49-1 | +27.4 |
| ShippingRush | 100% | 50-0 | +26.5 |
| TradeBuilding | 80% | 40-10 | +9.3 |
| ActionValue | 90% | 45-5 | +11.8 |
| 전체 | 94% | 234-16 | |

- 해석: Random, Factory, ShippingRush에는 거의 100% 승리함. 약한 상대는 TradeBuilding(80%)과 ActionValue(90%)이며, 둘 다 건물 위주 전략임.
- 가설: 제공된 PPO는 자기 자신과만 대전하며 학습했기 때문에, 건물 위주로 두는 상대를 학습 중에 거의 만나지 못했을 수 있음.
- 다음에 할 것:
  1. TradeBuilding에게 진 판을 열어서 어디서 밀리는지 확인
  2. 학습 상대에 TradeBuilding과 ActionValue를 섞어서 약점이 줄어드는지 실험


  ## 측정 방법 수정 (2026-11-05)

- 문제: 같은 Moka로 TradeBuilding과 50판을 다시 뒀더니 50승 0패가 나옴. 실험 0에서는 같은 상대로 40승 10패였음.
- 원인: play.py는 상대마다 다른 시드 묶음을 씀. 실험 0에서 TradeBuilding은 4000번대 시드였고, 다시 돌릴 때는 1000번대였음. 시드가 다르면 첫 총독과 농장이 나오는 순서가 달라짐. 시드 묶음을 바꿔 가며 50판씩 여러 번 재 보니 TradeBuilding 승률이 80~100% 사이로 움직였음. 50판으로는 10% 정도 차이는 운으로도 생길 수 있어서, 실력 차이인지 판 운인지 구분이 안 됨.
- 새 측정 기준:
  - 상대: TradeBuilding, ActionValue. 나머지 셋(Random, Factory, ShippingRush)은 거의 다 이겨서 개선돼도 숫자에 안 드러남.
  - 판수: 상대당 200판. 흔들림을 줄이기 위해 4배로 늘림.
  - 시드: 10000부터 고정. 앞으로 모든 실험에서 같은 판을 둬야 전후 비교가 가능함.
  - 200판도 흔들림이 ±5% 정도 남음. 실험할 때는 200판으로 보고, 좋아 보이는 결과는 1000판(시드 20000)으로 다시 확인하기로 함.

- 기준선 (새 기준):
| 상대 | 승률 | 승-패 | 점수 차 |
|---|---|---|---|
| TradeBuilding | 90% | 180-20 | +14.5 |
| ActionValue | 86% | 173-27 | +12.9 |

- 실험 0의 해석 수정: 실험 0에서는 TradeBuilding이 가장 어려운 상대라고 봤는데, 200판으로 다시 재 보니 ActionValue 쪽이 승률도 낮고 점수 차도 작음. TradeBuilding의 80%는 4000번대 시드가 불리했던 영향이 컸던 것으로 보임. "건물 위주 상대에 약하다"는 가설은 아직 버리지 않음. ActionValue도 건물 점수가 높은 봇이라서, 진 판을 직접 열어 보고 확인할 예정.
