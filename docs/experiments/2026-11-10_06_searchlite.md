# 실험 6: 탐색 봇(SearchLite)과도 연습하기 (2026-11-09 ~ 11-10)

## 목적

- Moka의 가장 낮은 승률은 탐색형 상대 (Moka v2 기준 SearchLite 59.7%, Search 57.5%). 다른 학생들도 forward model로 앞을 보는 에이전트를 만들 수 있음.
- 탐색 봇과 직접 연습하면 탐색형 상대에게 강해지는지, 그 대가로 다른 상대에게 약해지지 않는지 확인.
- 실험 5가 대조군. 출발점, 학습량, 학습률, 체크포인트 간격이 같고 상대 구성만 다름.

## 설계

- 출발점: E4b_30 (Moka v2)
- 상대 구성: 자기 자신 20%, SearchLite 10%, 나머지는 실험 5와 같음 (원본 5%, E3_10 5%, E3_20 10%, E3_30 10%, TradeBuilding 15%, ActionValue 15%, Factory 5%, ShippingRush 5%)
- 실험 5와 다른 점: 자기 자신 30% → 20%, SearchLite 0% → 10%
- 학습률 0.00001(학습 끝에 0까지 줄어듦), 600만 스텝, 100만마다 체크포인트 (E6_10 ~ E6_60)

명령:

```
python training/train_moka.py --num_players 2 --init_ckpt results/exp04b_pastself/checkpoints/ckpt_final.pt --pool_ckpts e3_10=...,e3_20=...,e3_30=... --opponents self:0.2,searchlite:0.1,orig:0.05,e3_10:0.05,e3_20:0.1,e3_30:0.1,tradebuilding:0.15,actionvalue:0.15,factory:0.05,shippingrush:0.05 --lr 1e-5 --total_timesteps 6000000 --ckpt_interval 1000000 --eval_interval 1000000000 --out_dir results/exp06_searchlite
```

## 학습

- 2026-11-09 12:15 ~ 11-10 00:10쯤, 11.96시간. 에러 없음. 체크포인트 7개 정상 저장.
- 첫 kl 0.0135. 실험 5(0.0131)와 같은 수준. 끝에는 실험 5처럼 0까지 내려감.
- 속도: 처음 약 103 sps → 충전기를 꽂고 "최고의 성능"으로 바꾼 뒤 145~152 sps. 배터리 모드에서 약 30% 느렸음 (탐색 봇이 섞이면 CPU를 계속 쓰기 때문에 차이가 더 큼). 실험 5(약 477 sps)보다 3배 이상 느림. SearchLite가 수마다 앞을 계산하는 동안 같은 프로그램의 나머지 게임도 기다리기 때문.
- 465만 스텝쯤부터 146 → 132 sps로 떨어짐. 같은 시간대에 노트북을 다른 용도로 쓴 것으로 보임.

- SearchLite 상대 승률이 꾸준히 오름: 시작 약 60% → 100만 64% → 300만 76% → 600만 89%.
- 초반(100~200만)에는 원본 상대가 실험 5보다 6~10%p 낮았음. 자기 자신 비율을 줄인 대가일 수 있다고 봤는데, 300만 이후에는 차이가 없어지고 끝에는 거의 같음. 다른 상대들도 600만 시점에서는 실험 5와 차이 없음 (모두 200판 흔들림 ±7%p 안).
- 주의: SearchLite는 학습 상대라서 89%는 "그 봇을 잘 이기게 됐다"일 수 있음. 학습에 쓰지 않은 Search, MCTS 상대 승률도 같이 올라야 탐색형 상대 전반에 강해진 것. 리그전과 최종 확인에서 따로 확인.
