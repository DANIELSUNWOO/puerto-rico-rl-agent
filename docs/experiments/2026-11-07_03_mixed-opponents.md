# 실험 3: 상대를 섞어서 이어서 학습하기 (2026-11-07)

## 목적

- 실험 1, 2에서 찾은 약점(건물 위주 상대, 탐색 봇)의 원인으로 "자기 자신과만 학습해서 다른 스타일의 상대를 거의 만나지 못했다"는 가설을 세움.
- 조교 체크포인트에서 이어서, 여러 상대와 섞어서 추가 학습하면 원본보다 강해지는지 확인.

## 학습 코드 수정 (training/train_moka.py, train_ppo.py 복사본)

- A. 이어서 학습하기: --init_ckpt 옵션 추가. 신경망을 무작위 숫자로 만든 직후 체크포인트 숫자로 덮어씀.
- B. 상대 섞기: --opponents 옵션 추가. 게임마다 상대를 비율대로 추첨.
  - 자기 자신과 둘 때는 양쪽 수를 모두 학습 자료로 쓰고, 봇과 둘 때는 학습 중인 쪽 수만 씀.
  - 게임마다 학습하는 쪽의 좌석(0번, 1번)을 무작위로 정함. 항상 0번 좌석이면 1번 좌석 경험이 부족해짐.
  - 봇에게는 대회 도구처럼 forward model을 넘겨줌. forward model은 숨겨진 농장 순서를 매번 무작위로 섞어서 보여 주므로 진짜 순서는 볼 수 없음.
  - 학습 중 상대별 최근 승률을 출력.
- 상대 비율: 자기 자신 40%, 원본(고정) 10%, TradeBuilding 15%, ActionValue 15%, Factory 10%, ShippingRush 10%.
  - Random은 너무 약해서 뺌. MCTS, SearchLite, Search는 한 판에 수십 초가 걸려서 이번엔 뺌 (SearchLite는 다음 실험 후보).
- 치팅 여부: 조교 체크포인트에서 출발하는 것은 수업 문서에서 허용 (보고서에 무엇을 바꿨는지 쓸 것). baseline을 학습 상대로 쓰는 것은 실험 2에 근거 정리.

## 시운전에서 찾은 것: 학습률

| 시운전 | 첫 번째 kl |
|---|---|
| 무작위로 시작, 학습률 0.0003 | 0.014 |
| 조교 체크포인트로 시작, 학습률 0.0003 | 0.72 |
| 조교 체크포인트로 시작, 학습률 0.00003 | 0.057 |
| 조교 체크포인트로 시작, 학습률 0.00001 | 0.013 |

- 같은 학습률인데 이미 학습된 신경망은 한 번에 50배 크게 바뀜. 조교 학습은 학습률을 0.0003에서 0까지 낮추며 끝났는데 다시 0.0003으로 시작한 것이 원인.
- 학습률 0.0003으로 짧게 돌렸을 때 원본 상대 승률이 50% → 29%로 계속 떨어짐. 0.00001에서는 50% 근처 유지.
- kl이 적정 범위(0.01~0.02)에 오는 0.00001로 결정.

## 관련 확인: greedy vs sampled

- 같은 신경망을 greedy(확률 1등 수)와 sampled(확률대로 추첨)로 붙임. 시드 100개 x 좌석 교대 200판.
- greedy 59.5%, sampled 40.5%. 대회에서는 greedy로 둠.
- 학습 중에는 sampled로 두기 때문에, 같은 실력의 원본(greedy)을 상대로는 40% 정도가 나오는 게 정상. 학습 중 승률을 해석할 때 이걸 감안해야 함.

### 측정 도구에 대해 알게 된 것

- course_ladder.py는 "한 쌍"을 하나의 작업으로 묶어서, 한 쌍의 판은 일꾼 하나가 처음부터 끝까지 혼자 둠. 그래서 SearchLite 1000판 같은 느린 쌍이 남으면 그 쌍 수만큼만 CPU를 씀 (이번엔 3개).
- 진행 줄도 쌍이 하나 끝날 때마다 찍혀서, 느린 쌍이 도는 동안 몇 시간씩 새 줄이 안 나올 수 있음. 멈춘 게 아님.
- 노트북은 충전기를 꽂고, 절전 "안 함", 전원 모드 "최고의 성능"으로 둬야 함. 배터리 모드에서는 CPU를 아껴 써서 느려짐.
